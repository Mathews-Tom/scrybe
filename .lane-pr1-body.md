Based on `main`. First of a five-pull-request series that gives the CLI and the read-only agent surface one shared application-service layer.

## What

Adds `scrybe-application` — published as `scrybe-meeting-application` — and the typed contracts the rest of the series implements against:

- **Opaque, root-confined session identity.** `SessionRef` validates at construction and refuses absolute paths, `/` and `\\` separators, `.`/`..` traversal, Windows drive-relative and alternate-data-stream syntax, home-relative `~` prefixes, and control characters. `StorageRoot::resolve` therefore produces a direct child of the configured root by construction rather than by a later check. Deserialization runs the same validation, so an identity arriving over a wire is held to the same rule as one built in process.
- **Self-clamping paging.** `PageRequest` clamps its limit into `1..=200` including when it arrives over the wire, so no consumer can ask a service to materialize an unbounded result set.
- **One error type with two audiences.** `ApplicationError` keeps a stable `ErrorCode` and a service-authored message; the originating error is retained privately as an `Error::source` for logs. `ErrorPayload` — the wire form — has no source, path, or cause field, so a provider URL or filesystem path cannot reach a frontend through an error channel.
- **Serializable session, configuration, diagnostics, and recording shapes.** `SessionDetail` carries state, artifact availability, capture and provider metadata, and repair/regeneration eligibility, and deliberately has no folder or path field. `DiagnosticFinding` carries `code`, `severity`, `component`, `summary`, `recovery_action`, and `mutation_required`. `RecordingState` encodes `Idle -> Preparing -> Recording -> Saving -> Completed -> Idle` with failure returning to `Idle`, and `RecordingEvent` carries a schema version, a sequence number, and timing only.
- **A configuration write surface that cannot name a secret.** `ConfigField` is a closed enum of thirteen GUI-owned fields. No variant addresses `[stt].api_key_env`, `[llm].api_key_env`, or any other credential-bearing key, so writing a secret is unrepresentable rather than merely disallowed. `ConfigForm` reports whether a hosted provider needs a credential as a boolean and omits the variable name entirely.

## Why the LoC ceiling entry lands here

`scripts/check-loc-budget.py` iterates its explicit `LOC_CEILINGS` table, not the workspace members list. An unlisted crate is silently uncounted — a fail-open default in a script whose purpose is to fail closed. Adding `"scrybe-application": 5200` in this pull request is what makes the rest of the series accountable to a budget at all. Neither the `scrybe-core` (16850) nor the `scrybe-cli` (7300) ceiling moves.

Measured after this change: `scrybe-application` 1341/5200, `scrybe-cli` 7105/7300, `scrybe-core` 16827/16850.

## Package identity and the publish check

`cargo publish --dry-run` verifies the package tarball against the **registry** copies of path dependencies, not the local workspace. A first attempt had `ConfigForm` borrow a `ShellIndicator` accessor that this branch made public in `scrybe-core`; the dry run correctly failed, because a published `scrybe-meeting-application 1.6.0` resolves `scrybe-meeting-core 1.6.0` from crates.io, where that accessor is private. Since this work must not finalize a release version, the `scrybe-core` change was reverted and the three-variant spelling is mapped locally instead — with a test that compares every variant against the spelling `scrybe-core`'s own `Serialize` implementation produces, so the mapping cannot drift silently.

## Plan revision

The pre-implementation measurement from `python3 scripts/check-loc-budget.py` on `54ba90c` is `scrybe-cli` 7,105/7,300 and `scrybe-core` 16,827/16,850. `scripts/check-loc-budget.py` iterates only its explicit `LOC_CEILINGS` table, so a new workspace member is silently uncounted rather than failing closed; the first stack entry therefore adds `"scrybe-application": 5200`. That ceiling covers typed serializable contracts, opaque identity, and errors; the paged cancellable session repository with classification, root confinement, and coalesced invalidation; the structure-preserving atomic configuration editor with rollback; structured diagnostic findings with a separate repair boundary; the versioned recording state model with idempotent stop; and the inline `#[cfg(test)]` coverage the script counts. Its scale is grounded in the 1,171 measured lines of `scrybe-core/src/agent_access` and the 1,758 measured lines of the migrating `scrybe-cli` `list`/`show`/`runtime`/`doctor`/`shell` surfaces, which this layer must generalize rather than copy. Neither the `scrybe-core` nor the `scrybe-cli` ceiling changes: the migration deletes the duplicated private scans and agent-access reads it replaces, so both crates must end the series net-neutral or smaller. Any need to exceed a ceiling is a material mismatch requiring a recorded reconciliation before the owning pull request merges.

The published package identity is `scrybe-meeting-application` in directory `scrybe-application`, matching the existing `scrybe-meeting-*` published-library convention (`scrybe-meeting-core`, `scrybe-meeting-capture-mac`, `scrybe-meeting-capture-mic`) while the binary crate keeps the bare `scrybe` name; both `scrybe-application` and `scrybe-meeting-application` resolve to HTTP 404 on the crates.io index API, so neither name is taken. Every package-qualified command therefore uses `cargo test -p scrybe-meeting-application`, because `-p` resolves package names rather than directory names.
